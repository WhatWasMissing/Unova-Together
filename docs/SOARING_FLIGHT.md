# Soaring flight preview

Soaring is an optional local flight scene for the English Black 2 Redux profile. The launcher starts a background worker that reads scenery from the player's own ROM. The emulator renders the resulting map locally and keeps flight movement separate from live game RAM until the player lands. Flight positions are not relayed to other players.

Enable **Soaring flight** in **Launcher → Settings → Experimental features**, restart, then open **Unova → Pokémon → Take flight**. Choose a healthy Flying-type Pokémon or one that knows Fly. The arrow keys steer and move, **A** boosts while moving forward, **L/R** change altitude, **X** selects nearby clear ground, and **B** opens the return-to-take-off choice.

## Native landing path

Landing uses the game's field-map event, so the game reloads the destination map, camera and terrain normally. The implementation is based on the user's Black 2 decomp at `F:\gen5decomps\pokebw2-main`:

- `src/ov036/scrcmd_mapchange.c`, `s028A_MapChangeFlyWarp`, shows Fly chaining into `EventMapChangeWarp_CreateGrid` with the destination zone and a `VecFx32` position.
- `include/field/event_mapchange.h` defines the native call as `(GameSystem*, Field*, zoneId, position, direction, unk40)`.
- `src/ov035/event_mapchange.c`, `EventMapChangeWarp_CreateGrid`, converts those coordinates into the regular map-change event.

`FieldTeleport` validates the Redux ROM and live field ownership, queues the guarded native event call, then confirms that the game reached the selected map and tile and remained stable before returning input to the player. It does not move the overworld actor by editing its cached coordinates. A separate map-warp ABI regression protects the argument and stack layout.

## World coverage and current limits

The background worker builds a 30×30 regional atlas from all 69 canonical outdoor matrix IDs found in the local Black 2 Redux 1.4.1 ROM. `MAP_MATRIX_OVERWORLD` and `MAP_MATRIX_OVERWORLD_2` use the same 29×27 chunk grid and 277 chunk IDs; the second matrix adds alternate gate-zone labels, which the exporter merges into the same world frame. The atlas is available from every outdoor matrix as a takeoff point.

Positions are based on reciprocal grid warps, decomp/Town Map or Fly markers, and 28 explicit placements for outdoor scenes that lack a unique connected warp path. Several story variants are grouped beside their related area to keep them visible; their exact in-world spacing is approximate. Three decorative flyways bridge the four groups found in the native warp graph. Flyways and sea/forest fill are scenery only and cannot be landed on. The launch map is given ownership when another overlapping map would otherwise hide its takeoff cell.

The exporter reads the decomp's WB, GC, and NG field-chunk containers. GC chunks contain two native collision layers and both are used for landing height. NG chunks contain a model and props but no collision terrain; their scenery is drawn and they are never landing targets. Castelia City 8 (matrix 7) and Victory Road 2 (matrix 162) use NG chunks, so their authored scenery renders while nearby WB/GC ground supplies landing sites. The static Nitro decoder now handles the multi-node transforms, matrix-stack operations and compact pivot rotations used by the five chunks that were missing before. For billboards it keeps the source plane and adds a crossed plane for camera coverage; texture environment/projection commands do not change the geometry. Empty cells inside the map footprint use the native Undella Bay `sea_mizu1` texture and palette. Space beyond the atlas remains the distant boundary.

Landing checks sample Black 2's native collision-height records instead of inferring ground from rendered triangles. `tools/import_soaring_height_tables.py` reads the decomp's `MAP_HEIGHT_SLOPE_TABLE` and `MAP_HEIGHT_OFFSET_TABLE`; `tools/soaring_geometry.py` uses them for WB, RD and GC chunk layouts, including stacked collision layers. It rejects blocked, water, steep, prop-covered and NPC-adjacent tiles. For flight approach, stacked valid layers currently choose the highest clear floor to avoid landing under bridges; compare this flight-specific choice against more live-game cases. The decomp marks Marine Tube as exterior but disables vanilla Fly-from there, and its Redux map has no safe landing tiles. Soaring still renders there; the menu reports when no clear ground is nearby and **B** returns to take-off.

## Verification

`tools/test_soaring_scene_worker.py` and `tools/test_soaring_geometry.py` cover extraction, all-map placement, takeoff-map ownership, streaming, collision and landing geometry. All 35 tests pass, including matrix-stack, pivot-rotation, gap-fill and matrix-owned zone-label regressions. A native RAM fixture confirms Black City's real map ID 0 remains usable and ordinary map fallback still resolves; the native scene check also loads and selects a landing on map 0. `soaring_warp_call.exe` passes the native Fly-warp ABI check. The final `tools/test_soaring_real_scene_matrix_set.py` sweep exported, loaded and rendered all 69 outdoor roots, exercised flight controls, and simulated landings on decoded clear ground. All 69 passed; Marine Tube (matrix 273) is the only map without a safe landing. Mid-flight scene reloads and both launcher-facing background worker checks also passed, including Black City. The slowest p95 was 15.16 ms on matrix 6 and the largest frame was 22.49 ms on matrix 2, both below the 33.3 ms frame budget. The exporter checks each landing's exterior area and owning matrix, so Black City's zone 0 is accepted on its own matrix while unrelated zero-filled labels are skipped. Use `--matrices <IDs...>` to rerun selected roots. The loader accepts up to 1,024 small textures while retaining a 16-million decoded-pixel cap; Redux matrix 416's 582-texture scene loads within that memory budget.

The matrix transforms follow the [Nitro SDK SBC command definitions](https://twlsdk.randommeaninglesscharacters.com/docs/nitro/NitroSystem/g3d/sbc/SBCCallback.html), with node and pivot encodings cross-checked against the [NSBMD format notes](https://github.com/scurest/nsbmd_docs/blob/master/nsbmd_docs.txt). Real-ROM exports of all five formerly unsupported chunks loaded in the native renderer. Four appeared in their regional flight scenes; chunk 0 was checked in an isolated export of its owning overworld matrix because the regional atlas masks that overlapping cell with another map. Each scene rendered 120 frames within the 33.3 ms frame budget; the slowest had a 14.1 ms p95 and a 20.8 ms maximum. Castelia City 8's NG chunk (114) and all four Victory Road 2 NG chunks (1061–1064) also render as scenery without generating collision. A live emulator flight across several areas, native landing and return-to-map playthrough are still needed before calling the feature fully validated. Test exports and previews belong in disposable test-fixture directories, never public release assets.
