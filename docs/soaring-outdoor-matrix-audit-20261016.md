# Soaring outdoor matrix audit — 2026-10-16

A read-only audit of the local English Black 2 Redux 1.4.1 ROM and the user's Black 2 decomp found 69 canonical matrix IDs used by outdoor zones. The decomp distinguishes whether an area's map is exterior from whether vanilla Fly can start in a zone: `data/areas/*.json` stores `exterior`; `data/zones/*.json` stores `fly_from`. `src/ov012/eventdata_system.c` rejects rail warps in `CheckWarpPositionMatch`, and `include/field/zone.h` separates grid and rail warp positions. Soaring has its own flight entry, so neither `fly_from` nor rail-only transitions should filter real outdoor scenery and grid links.

`MAP_MATRIX_OVERWORLD` and `MAP_MATRIX_OVERWORLD_2` have the same 29×27 grid and all 277 chunk IDs; the second matrix adds alternate per-cell zone labels for gates. The exporter merges those labels into one frame. The regional atlas is 30×30 and includes all 69 outdoor matrix IDs. Unique reciprocal grid warps and destination-warp coordinates establish exact translations where possible. Decomp/Town Map and Fly markers anchor additional outdoor places. Twenty-eight explicit supplemental placements cover scenes without one unique warp path: Castelia City sections, Twist Mountain, Desert Resort, Entrée Forest stages, Victory Road sections, the League approach, version gates, and standalone Hidden Grotto/Nature Preserve/Redux areas. Some separate story scenes are grouped beside their related area because the game data supplies no spatial outdoor warp for them; those local positions are approximate, not verified geography.

The native reciprocal-warp graph has four groups; three decorative flyways visually bridge them. Every one of the 69 canonical outdoor matrices can now serve as a takeoff root, and the offset audit resolves all 69 matrix IDs from each root. The exporter also prefers the active takeoff map only when the ordinary atlas ownership rule would hide its occupied launch cell. Story-scene placement remains approximate. Flyways, forest fill and the native sea backdrop have no collision and cannot be landing targets.

The atlas now has a repeatable footprint connectivity check in `audit_soaring_chunk_coverage.py`. On this ROM, its 30×30 atlas contains 440 authored map cells and 327 native sea-fill cells. Together they form one four-neighbour-connected surface; no empty cell is enclosed by the atlas footprint or touches authored map cells, including diagonally. The remaining 133 cells are connected to the atlas edge and represent the outer boundary. An all-roots check confirms that every one of the 69 outdoor matrices can be used as a takeoff root and produces the same 69 world placements after translating its local origin. The optional `--decomp F:\gen5decomps\pokebw2-main` check matches the matrix dimensions for all 68 original outdoor matrices. Matrix 416 is the one Redux-added outdoor matrix absent from the base decomp.

The native end-to-end sweep exported every outdoor root, loaded each scene through `SoaringScene`, rendered 120 views, exercised flight motion, selected and simulated a landing on decoded ground. All 69 roots passed on the final code. A real-ROM request/ready test confirmed the launcher-facing background worker returns scenes that the native loader can land in, including Black City. The Black 2 decomp defines `ZONE_BLACK_CITY = 0`; its area is exterior and its map matrix is 357. The exporter now validates each landing against both its exterior area and owning matrix, preserving Black City's genuine map 0 and filtering zero-filled labels belonging to other matrices. A synthetic native RAM regression also confirms the frontend tracker reports map 0 and still resolves an ordinary map from the entry-zone fields. Matrix 357 exposed adjacent zone records sharing a world tile; the native regression verifies the selected clear destination by world position while allowing its valid zone-local coordinates. Mid-flight scene reloads at matrices 6, 14, 225, 273, 357 and 416 retained the flight state, position and motion. Sixty-eight roots have safe ground; Marine Tube (matrix 273) has none and retains its return-to-take-off option. The final sweep's slowest p95 was 15.16 ms on matrix 6; its largest single frame was 22.49 ms on matrix 2, under the 33.3 ms frame budget. Run all roots with `py -3 -u tools/test_soaring_real_scene_matrix_set.py`; `--matrices <IDs...>` selects a subset. The existing 1,024-texture loader limit and 16-million decoded-pixel cap both passed, including Redux matrix 416 with 582 textures.

## Collision-height landings

Rendered terrain can contain vertically stacked surfaces in one map cell, such as a bridge above a road. The decomp's `src/ov036/field_map_chunk_height.c`, `include/field/field_map.h` and height/slope tables describe the native WB, RD and GC chunk records. `tools/import_soaring_height_tables.py` extracts those tables to `tools/soaring_height_tables.py`; `tools/soaring_geometry.py` samples tile centers and applies native collision flags, slope, terrain-class, prop and NPC-clearance checks.

For flight approach over stacked walkable layers, the sampler chooses the highest clear surface so it will not select a road beneath a bridge. The engine itself chooses a terrain layer relative to actor height, so more in-game examples should be checked before treating this flight-specific choice as final.

## Verification and limits

`py -3 -m unittest discover -s tools -p 'test_soaring*.py' -v` passes all 35 worker and geometry tests (30 worker, 5 geometry). The worker suite includes a regression that makes an unexpected export error, confirms the worker reports it to the game, then confirms it continues serving the next request. `py -3 tools/test_field_zone_native.py` compiles the frontend tracker against a synthetic Black 2 RAM image and verifies real map 0 plus ordinary-zone fallback. The 31 launcher UI tests pass with the local release-tools dependency path; they verify the launcher warns before closing while Soaring needs its worker and stops scenery workers after the game exits. `soaring_warp_call.exe` passes the native Fly-warp ABI regression. `py -3 tools/audit_soaring_chunk_coverage.py --rom <Black 2 ROM> --decomp <Black 2 decomp>` is the reusable ROM, atlas-footprint and decomp-dimension audit. The final audit's 30×30 atlas has 440 authored map cells, 327 native sea-fill cells and 133 outer-boundary cells; all covered cells form one connected component, with zero enclosed voids or uncovered cells next to mapped terrain. All 69 outdoor roots resolve identical placements; 68 original matrix dimensions match the decomp and matrix 416 is Redux-only. The 427 unique chunks comprise 361 WB, 45 GC and 21 NG; all decode, 406 with ground and 21 scenery-only. The final real-scene native sweep passed every root. A live emulator flight, landing and return-to-field playthrough remain to be verified.

Targeted real-ROM exports confirm Castelia City 8 (matrix 7) renders NG scenery from chunk 114 and Victory Road 2 (matrix 162) renders all four NG chunks (1061–1064). These NG chunks have no native collision or ground, so only neighboring WB/GC ground can provide landing sites. The new static node transforms follow Nitro SDK SBC command definitions and the reverse-engineered NSBMD node encoding; the audit confirms complete model decoding, not that every billboard matches each live camera angle. All five formerly unsupported chunks were exported into real scenes and accepted by the native renderer. Chunk 0 needed an isolated export of its owning overworld matrix because a different overlapping matrix masks that cell in the regional atlas. Each renderer run drew 120 frames within the 33.3 ms frame budget; across those runs, the slowest p95 was 14.1 ms and the maximum frame was 20.8 ms.

These are exporter, atlas and renderer checks. A live emulator flight through several areas, native landing, and map-return playthrough remain outstanding. Soaring is not yet fully validated for players. Temporary exports and screenshots must stay out of public release assets.
